# Manual game QA — 1 October 2026

## Scope and method

Test the live production build at `http://127.0.0.1:8101/` through Playwright
MCP. The original pass was diagnostic; the user subsequently authorized fixes
with mandatory manual retesting. Preserve
the current working tree. Do not use passing geometry scripts as proof of
manual usability or real-world visual fidelity.

Use normal button, keyboard and pointer input for behavior. The existing debug
teleport may position the rider for a location test, but is not evidence of
walkable access. Record the teleport separately and walk the actual boundary.
Read-only debug state may measure movement, collision and delivery results.
Never edit game state to force a pass. Capture screenshots and reproduction
steps for failures; distinguish observed failures from unverified concerns.

## Severity and evidence

- P0: cannot load/play, crash, data loss.
- P1: core movement/delivery blocked, escape/collision failure, stuck input.
- P2: significant visual/camera/layout defect, confusing controls.
- P3: polish/accessibility inconsistency.

Each finding must include build, viewport, setup, input sequence, expected vs
actual, repeatability and evidence filename. Screenshots alone do not prove
collision, performance or geographic accuracy. Browser automation timing is
not a reliable frame-rate benchmark.

counts progressed 0→1→2→3→4 with +5s bonuses. No counters were manipulated.

collider; do not merely round the distance differently or disable collisions.

### QA-002 — Input lifecycle gap; original browser evidence corrected

**Reproduction:** In desktop play, hold W; open/focus a second browser tab;
release W in that other tab; return to the game without another movement key.
Test setup was `(5,5,0)`.

**Expected:** Losing focus clears held input; returning does not move the rider
without input. **Actual:** `inputActive=true` after return and with no new key
press. Theta increased `6.080147821→6.268441689` during the next 1.2-second
observation, speed increased `.7054→.8040`, animation remained `walk`.
Sending a W keyup to the game recovered control. **Correction:** Playwright
emulated focus in both tabs, so this original sequence did not deliver an
actual blur event. It does not establish a real tab-focus reproduction.

Evidence: [post-focus screenshot](qa-evidence/2026-10-01/qa-focus-loss.png);
the state/time observations above, not the still screenshot, prove motion.
Code inspection found missing blur/visibility cleanup in the original controls.
